# In-world models (Unity build)

This folder holds custom 3D models for the mods, ready for Foxy Voxel's Unity modding project ([FoxyVoxel/going-medieval-modding](https://github.com/FoxyVoxel/going-medieval-modding), MIT). The game loads custom meshes and textures only as Unity Addressables, so they need one build in Unity. The mods work without it: until the Addressables exist, the buildings keep their vanilla models.

| Mod | Model | Replaces |
|---|---|---|
| Cold | `Cold/Texture/phrontisteries_cold_shelf_albedo.png`: a frosted, blue-tinted copy of the game's shelf texture (`base_texture_png`). The Cold Shelf keeps the game's own `shelf` model, pile slots and shader settings; only its albedo texture changes. | the vanilla shelf's wood colours on the Cold Shelf (1×1) |
| Fish_Farming | `Fish_Farming/Mesh/phrontisteries_fish_farm.obj`: a large empty staved tub with a plank floor, a feed sack, a bucket and a net, filling the farm's 3×3 tiles. While the farm produces, the game plays its built-in working effect (the saltpeter pit's), as the stage visual. | the saltpeter-pit model on the Fish Farm (3×3) |

Each custom model has a palette texture in `Texture/` (`<mesh>_palette.png`), generated by `tools/art/make_art.py` (models in `tools/art/models.py`).

The Cold Shelf texture is made from the game's own texture:

```
pip install UnityPy
python tools/art/extract_game_texture.py "<Going Medieval>/Going Medieval_Data/StreamingAssets/aa/StandaloneWindows64" work base_texture_png
python tools/art/recolor_texture.py work/base_texture_png.png unity/Cold/Texture/phrontisteries_cold_shelf_albedo.png frost "#7AB4FF" 0.5 1.6
```

The arguments are the frost colour, how strongly it washes over the wood (0–1) and the contrast (1 = unchanged); change them for another look. The mod cannot load a loose texture file: the game only reads loose PNGs from `Data/Sprites` (icons). Building textures and meshes must come through Addressables, hence the Unity build below.

The Cold Floors (one per vanilla floor) use frosted copies of the game's floor textures: on each floor the most elements possible with no two touching (planks, flagstones, blocks, bricks, tiles, triangles, panels, strands or bar segments) are frosted, spread evenly, in the colour of the Cold Shelf's frosted boards. Floor textures are projected in world space, so each pattern runs across every floor piece (full, corner, edge, end, line, single).

- `Cold/Texture/phrontisteries_cold_floor_sheet.png`: the game's 4x4 floor sheet (`FloorDiffuseSheet`) with the square of every floor that uses it frosted (wood, wicker, limestone, limestone block, clay brick, metal grate, wicker mesh). Those floors keep their square, bump map and tiling; their shader tint is baked into the copy and reset on the Cold Floor.
- `Cold/Texture/phrontisteries_cold_<floor>_albedo.png`: frosted copies of the decorative floors' own textures, with rules of their own:
  - decorative stone: only the circle of each large rosette (and its four corner dots) and the middle squares; the tiny mosaic tiles never
  - decorative clay: only the circles: of each large circle (and its corner dots) and of the complete-circle tiles; the fleur tiles never
  - marble: the dark triangles, and the round medallions where four triangles meet frosted solid

```
python tools/art/extract_game_texture.py "<...>/aa/StandaloneWindows64" work FloorDiffuseSheet painted_stone_tile_diffuse painted_clay_tile_diffuse marble_floor_diffuse
python tools/art/make_cold_floors.py --info "<...>/StreamingAssets/Constructables/BaseBuildingRepository.json" work/floors.json
python tools/art/make_cold_floors.py work unity/Cold/Texture "#948B83" preview.png
```

The icons are made from the game's own icons (export them by their `iconPath` names with `extract_game_texture.py`), with the snowflake badge of the Cold set:
- Cold Floors (`recipes/Cold/Sprites/phrontisteries_cold_<floor>.png`): the floor icon with a light frost tint: `python tools/art/make_cold_floor_icons.py <icon dir> recipes/Cold/Sprites <floor ids...>`
- Cold Shelf (`recipes/Cold/Sprites/phrontisteries_cold_shelf.png`): the shelf icon with the shelf in its in-game frosted blue-grey: `python tools/art/make_cold_shelf_icon.py <icon dir>/shelf.png recipes/Cold/Sprites/phrontisteries_cold_shelf.png`

The Cold preview (`recipes/Cold/Preview.png`) is drawn by `tools/art/make_art.py` from the game's shelf model and floor textures (set `GM_ART_WORK` to the folder they were exported to).

Until the frosted textures are in the built Addressables, the Cold Floors fall back to a cool tint of the vanilla floors (floor shader colour parameters).

## Build steps (once per change to a model)

1. Install **Unity 2022.3.46f1** through Unity Hub, with **Windows Build Support (Mono)**.
2. Get [FoxyVoxel/going-medieval-modding](https://github.com/FoxyVoxel/going-medieval-modding) (clone or **Code > Download ZIP**), then in Unity Hub **Add > Add project from disk** and open it. The first import takes several minutes.
3. In the **Addressable Builder** window (or **Going Medieval > Addressable Builder**), click **Create New**, name the mod exactly as its folder (`Cold`, `Fish_Farming`) and click **Create**. This makes `Assets/Mods/<Mod>/` with `Mesh`, `Sprite`, `Texture` and `Exported` folders. Do not add other folders there: the builder only knows those names.
4. Drag the files from this repo's `unity/<Mod>/Mesh` and `unity/<Mod>/Texture` into the matching folders in Unity's **Project** window. Keep the default import settings: they match the game's own textures (sRGB, mipmaps, bilinear, normal compression).
5. In the **Addressable Builder**, select the mod and click **Create Addressables**. Optional check: **Window > Asset Management > Addressables > Groups** shows the mod's group with each file's name as its address and a `Texture` or `Mesh` label.
6. With the mod still selected, click **Build**. The output (a `catalog_*.json`, a `.hash` and one or more `.bundle` files) lands in `Assets/Mods/<Mod>/Exported/`.
7. Copy the contents of `Exported/` into this repo's `recipes/<Mod>/AddressableAssets/` and rebuild: `.\MakeMod.ps1 -ModName <Mod>`. MakeMod sees the catalog, copies it to `Data\AddressableAssets`, and switches the building to the custom assets (`Set-ModelTexture` for the Cold Shelf, `Set-ModelMesh` for the Fish Farm).
8. Test in game, then commit `recipes/<Mod>/AddressableAssets` and the rebuilt mod.

## Builder fixes (unity/patches)

Foxy Voxel's Addressable Builder (as of their June 2025 release) could freeze the editor: it saves the Addressables settings on every redraw and refreshes on focus, so two builder windows kept refreshing each other ("Not Responding"). Its **Refresh** button also dropped the request ("Skipping Refresh() - not in a valid Unity GUI event"). `unity/patches/AddressableBuilder.cs` and `AddressableWindowChecker.cs` fix both. Copy them over the files in the project's `Assets/FoxyVoxel/NSMedieval/Editor/`. If the editor is already frozen, end Unity in Task Manager and delete `Library/CurrentLayout-default.dwlt` before reopening.

When **Build** asks whether to turn on Debug Build Layout, choose No.

## Notes

- The models are `.obj`. Unity imports OBJ directly. Foxy Voxel's guide mentions FBX; the OBJ files are meant to be used as they are (see the mirroring note).
- Units are metres with Y up, measured from the building's origin tile at floor level. Multi-tile buildings sit one or more tiles in from the origin: the 3×3 fish farm is centred at (1, 0, 1), matching its collider.
- Unity's OBJ importer mirrors X, so the `.obj` files are pre-mirrored and arrive in Unity exactly as drawn. Import them directly; a round trip through Blender would mirror them back.
- Production stages: the game cannot swap a building's model per stage. A building has one model, plus an optional built-in effect while it works (`productionEffectPrefabId` in ProductionComponentsRepository). Mods cannot add new effects; the Addressables system only takes meshes, textures and sprites.
- Asset names: Foxy Voxel's builder uses each file name, without extension, as its address. The recipes reference `phrontisteries_cold_shelf_albedo`, `phrontisteries_cold_floor_sheet`, `phrontisteries_cold_<floor>_albedo`, `phrontisteries_fish_farm` and `phrontisteries_fish_farm_palette`, so keep those names.
- The textures in `Cold/Texture/` are recoloured copies of Foxy Voxel's game art, shipped only for use with the game. They are not covered by this repo's MIT licence.
- Untested so far: whether the game's shader likes the palette texture with empty reflection and emission slots, and the exact pivot the game expects. Check both on the first in-game test.
